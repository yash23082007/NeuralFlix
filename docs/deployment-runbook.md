## Environment Variables

### Backend (Render)

| Variable | Required | Description |
|:---|:---:|:---|
| `DATABASE_URL` | ✅ | PostgreSQL connection string (auto-set by Render) |
| `JWT_SECRET` | ✅ | Auto-generated by Render, used for token signing |
| `TMDB_API_KEY` | ✅ | TMDB v3 API key |
| `TMDB_READ_ACCESS_TOKEN` | ⬜ | TMDB v4 bearer token |
| `OMDB_API_KEY` | ⬜ | OMDb API key for multi-source ratings |
| `WATCHMODE_API_KEY` | ⬜ | Watchmode API key for streaming availability |
| `TRAKT_CLIENT_ID` | ⬜ | Trakt OAuth client ID |
| `REDIS_URL` | ⬜ | Redis connection URL (optional; graceful fallback) |
| `CORS_ORIGINS` | ⬜ | Comma-separated allowed origins |
| `LITE_MODE` | ⬜ | `true` (default) = skip heavy ML model loading |
| `NEURALFLIX_DEMO_MODE` | ⬜ | `true` = use SQLite, skip Redis requirement |
| `ENABLE_NCF` | ⬜ | `false` (default) = disable neural collaborative filtering |
| `ENABLE_EXPERIMENTAL_ML` | ⬜ | `false` (default) = disable BERT sentiment reranker |
| `PYTHONUNBUFFERED` | ⬜ | `1` = real-time log output |

### Frontend (Vercel)

| Variable | Required | Description |
|:---|:---:|:---|
| `NEXT_PUBLIC_API_URL` | ✅ | Backend API base URL |

## Deployment Steps

### Render (Production)

**Automatic deployment (recommended):**

1. Push to `main` branch — Render auto-deploys on merge
2. Monitor build: Render Dashboard → Services → `movie-recs-backend` → Events
3. Verify health: `curl https://neuralflix.onrender.com/health/ready`

**Manual deployment:**

1. Navigate to Render Dashboard → `movie-recs-backend`
2. Click **"Manual Deploy"** → Select `main` branch
3. Wait for build to complete (typically 2-3 minutes)
4. Verify all health endpoints (see [Health Checks](#health-checks))

**Database migration:**

1. Connect to Render shell or use `render ssh`
2. Run: `cd backend && python -c "from database import init_db; import asyncio; asyncio.run(init_db())"`
3. Optional seeding: `POST /api/v1/seed` endpoint

### Vercel (Frontend)

**Automatic deployment:**

1. Push to `main` — Vercel auto-deploys
2. Preview deployments created on PRs automatically
3. Verify: Visit `https://neural-flix.vercel.app`

**Environment variable update:**

1. Vercel Dashboard → Settings → Environment Variables
2. Update `NEXT_PUBLIC_API_URL` if backend URL changes
3. Trigger redeploy: Settings → Deployments → Redeploy

### Local Docker (Development)

```bash
# Start all services
docker-compose up -d

# Check status
docker-compose ps

# View logs
docker-compose logs -f backend

# Stop
docker-compose down
```

## Rollback Procedures

### Backend (Render)

1. Navigate to Render Dashboard → `movie-recs-backend` → **Events**
2. Find the last successful deploy
3. Click **"Rollback to this deploy"**
4. Verify health endpoints post-rollback

**If Render UI is down:**

```bash
# Revert the commit locally
git revert HEAD
git push origin main
# Render will auto-deploy the reverted commit
```

### Frontend (Vercel)

1. Vercel Dashboard → Deployments
2. Find the last working deployment
3. Click **"..."** → **"Promote to Production"**

### Database Rollback

> ⚠️ **No automatic database rollback.** Destructive schema changes must be reviewed and tested in staging first.

If data corruption occurs:
1. Contact Render support for point-in-time recovery (if on paid plan)
2. Or restore from the latest backup (see Database Operations)

## Health Checks

### Endpoints

| Endpoint | Purpose | Expected Response |
|:---|:---|:---|
| `GET /health/live` | Liveness (is process running?) | `{"status": "alive"}` |
| `GET /health/ready` | Readiness (are deps healthy?) | `{"status": "ready", "database": true, ...}` |
| `GET /v1/metrics/health` | Alias for readiness | Same as above |
| `GET /` | API metadata | `{"name": "Movie Intelligence Platform ML Engine", ...}` |

### Post-Deploy Verification Script

```bash
BASE="https://neuralflix.onrender.com"

echo "1. Liveness..."
curl -sf "$BASE/health/live" | jq .status

echo "2. Readiness..."
curl -sf "$BASE/health/ready" | jq .

echo "3. API root..."
curl -sf "$BASE/" | jq .version

echo "4. Onboarding recs..."
curl -sf "$BASE/api/v1/recommendations/onboarding?limit=3" | jq '.recommendations | length'

echo "5. Cinema trails..."
curl -sf "$BASE/api/v1/cinema-trails" | jq .total

echo "All checks passed ✅"
```

### Automated Monitoring

Render provides automatic health checking via the Docker `HEALTHCHECK` directive.
Configure external uptime monitoring (e.g., UptimeRobot) to ping `/health/live` every 5 minutes.

## Incident Response

### Severity Levels

| Level | Description | Response Time | Example |
|:---|:---|:---|:---|
| **P1 — Critical** | Service fully down | Immediate | Backend not responding |
| **P2 — Major** | Core feature broken | < 1 hour | Recommendations returning empty |
| **P3 — Minor** | Non-core degraded | < 4 hours | OMDb ratings unavailable |
| **P4 — Low** | Cosmetic/minor | Next sprint | Streaming badge not loading |

### P1 Response Checklist

1. **Check Render status page** — Is there a platform incident?
2. **Check `/health/live`** — Is the process responding at all?
3. **Check `/health/ready`** — Which dependency is down?
4. **Check Render logs** — Look for unhandled exceptions
5. **If database is down** — Check Render DB dashboard for connection limits
6. **If Redis is down** — System should continue without cache (graceful fallback)
7. **If nothing works** — Rollback to last known good deploy (see Rollback section)

### P2 Response: Empty Recommendations

1. Check if the database is seeded: `GET /api/v1/recommendations/onboarding`
2. If empty, trigger seed: `POST /api/v1/seed`
3. If seeded but still empty, check logs for ML pipeline errors
4. Verify TMDB API key is valid: check environment variables

## Database Operations

### Seeding (First Deploy)

```bash
# Via API endpoint
curl -X POST https://neuralflix.onrender.com/api/v1/seed

# Via script (if shell access)
cd backend && python scripts/seed_database.py
```

### Backup

Render managed PostgreSQL provides automatic daily backups on paid plans.
For manual backup:

```bash
pg_dump $DATABASE_URL > backup_$(date +%Y%m%d).sql
```

### Reset (Development Only)

```bash
# ⚠️ DESTRUCTIVE — only for dev/staging
rm backend/neuralflix.db
python -c "from database import init_db; import asyncio; asyncio.run(init_db())"
curl -X POST http://localhost:8000/api/v1/seed
```

## Common Troubleshooting

### Backend won't start

| Symptom | Cause | Fix |
|:---|:---|:---|
| `ModuleNotFoundError` | Missing dependency | Check `requirements.txt`, rebuild |
| `Connection refused` on DB | DB not provisioned | Verify `DATABASE_URL` env var |
| `JWTError` on all requests | Wrong `JWT_SECRET` | Ensure same secret across deploys |
| Port already in use | Previous instance | Kill process or use different port |

### Frontend can't reach backend

| Symptom | Cause | Fix |
|:---|:---|:---|
| CORS error in console | Origin not allowed | Add frontend URL to `CORS_ORIGINS` |
| Network error | Wrong `NEXT_PUBLIC_API_URL` | Verify env var on Vercel |
| 401 on all requests | Cookie not sent | Check `credentials: "include"` in fetch calls |
| Cookie not set | HTTPS mismatch | Ensure both frontend and backend use HTTPS in prod |

### Recommendations are empty

1. Check onboarding endpoint (no auth needed): `GET /api/v1/recommendations/onboarding`
2. If onboarding works but personalized doesn't: user may have no watch history
3. If everything is empty: database needs seeding (`POST /api/v1/seed`)
4. Check TMDB API key validity

### Redis errors in logs

Redis is **optional**. Warning logs like `redis_unavailable_during_startup` are expected when Redis is not configured. The system operates fully without Redis — it just won't cache responses.
